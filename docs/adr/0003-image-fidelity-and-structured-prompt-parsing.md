# 0003: 反推图像画质保真策略、结构化输出双重容错与截图交互设计

## 状态
已通过 (Accepted)

## 上下文与问题陈述
在进一步细化反推链路与采集交互时，需要明确解决以下三个核心技术与用户体验问题：
1. **缩略图对反推质量的潜在破坏**：缩略图（如 400px）虽然能加速列表渲染，但下采样会抹平微观艺术笔触、胶片颗粒、水彩晕染与局部材质，严重破坏多模态模型对高阶画风的感知。
2. **多模态结构化 Prompt 输出的稳定性**：Vision 模型同时承担图像推理与格式约束，单纯依靠正则提取 Markdown 极易因客套前缀或换行解析失败。
3. **截图采集的非侵入性交互**：强制绑定全局快捷键会严重侵入用户操作系统、IDE 或其他网页快捷键生态，需要平衡易用性与用户主权。

## 决策 (Decision)

### 1. 图像画质保真策略（双轨分流）
- **展示轨**：入库时前端 Canvas 异步生成一张 400px WebP 缩略图存入 IndexedDB，仅用于侧边栏双列瀑布流的高帧率流畅渲染，避免大图撑爆 DOM 显存。
- **反推轨**：**默认使用全分辨率原图直接发送至多模态 Vision 模型**，保留全部原始细节与艺术微观特征。仅设置高阶安全阈值（如最长边 > 3840px 4K 或 Base64 > 15MB）时进行保护性边界缩放，防止前端内存溢出。

### 2. 结构化输出协议与三级弹性容错解析 (Robust Dual Parser)
- 请求侧：调用接口时显式传递 `response_format: { type: "json_object" }`，并在 System Prompt 中严格指定四个核心积木字段：
  - `subject` (主体)
  - `style_medium` (画风与媒介)
  - `lighting_mood` (灯光与氛围)
  - `composition_color` (构图与色彩)
  - `full_prompt_narrative` (叙述流完整串联)
  - `full_prompt_tags` (标签流完整串联)
- 解析侧：前端执行三级降级防护：
  1. 优先直接 `JSON.parse()`；
  2. 若模型输出被代码块包裹，正则剥离 ```` ```json ... ``` ```` 提取 JSON 内容；
  3. 极端容错：若 JSON 损坏，将整段文本兜底放入主体区域，绝不报错阻断。

### 3. 截图交互：侧栏常驻按钮优先，快捷键交由用户自主设置
- 侧边栏顶部常驻显式「网页区域截图」相机按钮，一键调出轻量半透明十字框选蒙层。
- 不由插件硬编码默认全局快捷键；在设置页提供引导链接 `chrome://extensions/shortcuts`，由用户按需自主绑定。

## 后果 (Consequences)
- 极大提升反推 Prompt 的细节颗粒度与艺术保真度；
- 彻底消除解析报错与白屏风险；
- 尊重用户操作习惯，杜绝快捷键冲突风险。
