# 0009: 独立全屏生图工作台与无限画布演进架构

## 状态
已通过 (Accepted)

## 上下文与问题陈述
随着 PicPocket AI 生图工作台能力的持续演进，用户在日常创作中面临严重的视口与交互瓶颈：
1. **侧边栏视口物理狭窄（340px~420px）**：
   - 包含长自然语言叙事提示词（50~150 词）、参考图托盘、多比例切换与高级配置项时，发生严重垂直挤压，长文本编辑痛苦；
   - 每次生成 1~4 张候选图片时，只能在单列中垂直堆叠，用户无法横向并排对比微观纹理与光影差异；
   - 缺乏“参考图 ➔ 反推 ➔ 生图 ➔ 垫图迭代”的可视化拓扑演进心智。
2. **需要兼顾轻量与重度两种心智**：
   - 用户在网页随手收集、查看单张图片时，侧边栏是轻量敏捷的最佳形态；
   - 用户在进行重度长提示词微调、多候选图挑选、大画幅细节检视时，需要 100% 浏览器全宽（1080P/2K/4K）的独立沉浸创作环境。
3. **文案表达与国际化守则**：
   - 严禁堆砌“工坊”、“矩阵”、“空间”、“引擎”、“沉浸式”、“赋能”、“沉淀”等 AI 假大空词汇与中二台词，严格遵守「好好说话」规范；
   - 严禁 JSX 裸写中文字符串，所有文本必须受 `TranslationKey` 与双语字典强约束。

## 决策 (Decision)

我们决定采用渐进式两步走（Two-Phase）演进路线：

### 1. Entrypoint 架构：独立全标签页 (`workbench.html`)
- 在 `src/entrypoints/workbench/` 建立独立的 WXT Entrypoint，产物生成 `dist/chrome-mv3/workbench.html`；
- 与 `sidepanel.html`（侧边栏）及 `options.html`（设置中心）形成三足鼎立的职能划分：
  - `sidepanel.html`：快速采集、轻量反推、快速垫图；
  - `options.html`：API 凭据、服务商、偏好与存储冷备份；
  - `workbench.html`：宽屏生图、双图比对、无限画布创作。

### 2. 侧边栏入口显眼度与引导体系 (Prominence & Guidance)
- **顶栏常驻显眼操作胶囊**：在侧边栏生图 Tab 顶栏放置高对比度呼吸微光胶囊 `[ ⛶ 全屏打开工作台 ]`（或单屏显眼图标），杜绝易被忽视的幽灵按钮；
- **首次进入可关闭提示条 (Dismissible In-situ Banner)**：在生图工作台首次载入时，以温和非阻塞卡片提示：*“侧边栏太窄施展不开？点击全屏打开工作台，享受宽屏大图与多图对比”*，点击关闭后将状态记录到本地存储，后续不再打扰。

### 3. 会话接力与单例激活 (Seamless Handoff & Singleton Navigation)
- **单例防重复开标签页**：通过 `chrome.tabs.query({ url: ... })` 探测是否已存在打开的 `workbench.html`，若存在则直接调用 `chrome.tabs.update(tabId, { active: true })` 聚焦窗口，杜绝开出僵尸标签页；
- **草稿无损同步**：侧边栏当前填写的 Prompt、多参考图托盘及参数，在点击全屏打开时自动通过 Storage / URL Hash 状态传递，新页面即时接管，创作零断点；
- **后台长任务接管**：Service Worker 后台运行的任务在全屏大页面载入时通过数学时间差绝对对齐，继续平滑展示倒计时与生成结果。

### 4. 第一阶段架构：轻量无限画布创作工作台 (Simple Infinite Canvas)
- **拒绝传统死板三栏并排**：根据用户决策，彻底摒弃传统固定三栏布局，直接参考 `basketikun/infinite-canvas`（MIT 开源协议）构建支持二维无限平移与平滑缩放（Pan & Zoom，20%~300%）的轻量网格画布；
- **主生图控制台节点 (Generator Card)**：中央浮动卡片承载模型选择、多参考图托盘、画幅比例与长 Prompt 编辑，支持自由拖动与位置记忆；
- **自由结果图片卡片 (Image Node Cards)**：候选生成图以独立图片卡片自由散落于画布上，支持鼠标自由拖拽重新排布、双击原始大图放大查看、一键保存至图库、设为垫图主参考图继续衍生；
- **原生快捷键系统**：
  - `Space + 拖拽 / 滚轮`：平移视口与平滑缩放；
  - `Cmd/Ctrl + Enter`：全局触发立即生图；
  - `Delete / Backspace`：非破坏性删除选中的单张图片卡片；
  - `Cmd/Ctrl + 0`：重置中心视口 (100%)；
  - `Esc`：关闭大图 Lightbox 或取消选中。

### 5. 后续演进：高级节点连接与 MCP Agent 联动 (Node-Flow & MCP)
- 逐步引入节点间连线（Bezier Curves / Orthogonal Edge）与工作流分支（反推 ➔ 提示词修饰 ➔ 多模型并发衍生）；
- 结合本地 MCP Bridge 协议，支持外部 AI Agent（Cursor / Claude Code）向画布直接分发、编排或修改生图节点。

## 后果 (Consequences)

### 正向影响
- 彻底释放生图体验，长提示词、多参考图、大画幅高清对比不再受到 380px 狭窄侧边栏限制；
- 保持数据与会话 100% 同源无损流转，利用浏览器 IndexedDB 与 Service Worker 达成零成本状态打通；
- 从架构上打通面向未来“无限节点画布”的平滑演进通道。

### 潜在代价与注意事项
- 新增 Entrypoint 略微增加扩展打包总体积（约 80KB ~ 150KB Chunks）；
- 必须严格遵守 MV3 异步存储与单例激活规则，防止并发覆写草稿。
